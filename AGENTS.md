# Работа агентов в репозитории

Координатор отвечает за задачу до принятого результата. Планирование, исследование, реализацию, тестирование, ревью и Git-операции поручает субагентам. Сам он определяет границы работ, согласует зависимости между исполнителями, проверяет доказательства и сообщает итог пользователю. Правила распространяются на код, документацию и саму инфраструктуру.

[Руководство по использованию и переносу](agent-infra/README.md) описывает путь от постановки задачи до выпуска и состав комплекта.

## Перед началом

Выбирать маршрут по задаче. Встроенные примеры внешних skills подчиняются правилам проекта: для каждого коммита действуют русский заголовок и подробное русское тело. Ранее порученные Git-действия выполнять в пределах согласованного процесса без повторного согласования.

| Задача | Что читать локально |
|---|---|
| Рабочая ветка, коммит, завершение PR | [Правила Git](agent-infra/git.md). Для изоляции параллельных правок использовать [using-git-worktrees](agent-infra/skills/using-git-worktrees/SKILL.md), при подготовке коммита — [git-commit](agent-infra/skills/git-commit/SKILL.md), перед интеграцией — [finishing-a-development-branch](agent-infra/skills/finishing-a-development-branch/SKILL.md). |
| Проверка Go-кода, SQL и браузерного клиента | [Порядок тестирования](agent-infra/testing.md) и Go-скилл из [локального каталога](agent-infra/SOURCES.md). Для сквозного браузерного сценария использовать [webapp-testing](agent-infra/skills/webapp-testing/SKILL.md). |
| Независимая проверка плана или PR | [Порядок ревью](agent-infra/review.md) и цикл ниже. Для изменений на границах доступа или доверия дополнительно использовать [differential-review](agent-infra/skills/differential-review/SKILL.md). |
| Версии, лицензии и источники skills | [Реестр локальных материалов](agent-infra/SOURCES.md). |

1. Прочитать [правила Git](agent-infra/git.md). Исполнителю передать требование пользователя, критерий приёмки, исходный SHA, разрешённые пути и подходящие локальные skills. Записывать конкретные команды проверок с учётом проекта.
2. Проверить рабочее дерево и индекс. Сохранить чужие изменения. Для параллельной правки пересекающихся файлов выделить отдельные worktree либо выполнять задачи последовательно.
3. Для многошагового изменения применить [writing-plans](agent-infra/skills/writing-plans/SKILL.md). На ревью плана передать сам документ, требования и ссылки на исходники. Начинать реализацию согласованного плана только после чистого независимого ревью его текущей версии и в пределах порученной задачи.

## Реализация и тесты

Применять [test-driven-development](agent-infra/skills/test-driven-development/SKILL.md). Тест на регрессию сначала воспроизводит дефект. Характеризационный тест перед рефакторингом проходит на исходном коде и сохраняет наблюдаемое поведение. Тесты и соответствующее изменение проходят в одном PR. Для документации проверять инструкции, примеры и локальные ссылки.

Для Go выбирать уровень, на котором видно нарушение контракта: табличный тест для логики, httptest для HTTP, реальная временная БД для SQL и прав доступа. Базовые команды — `go test ./...` и `go vet ./...` из корня соответствующего модуля. Изменения конкурентного кода проверять через `go test -race ./...` в поддерживаемой среде. Указывать пропущенные проверки и причину.

## Независимое ревью до чистого результата

1. Координатор выделяет **нового субагента на каждую итерацию**. Ревьюер получает требования, весь итоговый diff от базы, SHA проверяемой версии, результаты тестов и [шаблон ревью](agent-infra/skills/requesting-code-review/code-reviewer.md). Для плана или незакоммиченной работы идентифицировать снимок по содержимому файлов. Автор и предыдущие ревьюеры не выступают финальным ревьюером своей работы.
2. Ревьюер читает [requesting-code-review](agent-infra/skills/requesting-code-review/SKILL.md), проверяет изменения по исходникам, оценивает сохранение контрактов и полноту тестов. Возвращает конкретные замечания с последствиями и местом либо явное «замечаний нет».
3. Исполнитель разбирает каждое замечание по [receiving-code-review](agent-infra/skills/receiving-code-review/SKILL.md). Ошибку исправляет и проверяет; для спорного вывода предоставляет проверяемые основания. Следующий независимый ревьюер получает полную обновлённую работу. Продолжать до явного чистого заключения. Изменение содержимого после такого заключения требует новой проверки.
4. Перед завершением применить [verification-before-completion](agent-infra/skills/verification-before-completion/SKILL.md). Сообщить версию, выполненные команды, их результаты, результат независимого ревью и фактический статус интеграции.

## Перенос в другой проект

Копировать этот файл вместе с каталогом `agent-infra/` в корень репозитория. Если у проекта уже есть AGENTS.md, объединить инструкции с сохранением проектных правил. Skills читать из локальной копии. Примеры команд внешних авторов адаптировать под текущую оболочку, язык коммитов и модель веток проекта.
