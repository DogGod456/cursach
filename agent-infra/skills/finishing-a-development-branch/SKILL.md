# Завершение ветки

Перед Git-операциями прочитать [правила проекта](../../git.md). Получить явное чистое [ревью](../../review.md) и результаты проверок на текущем SHA. Проверить базу и полный diff ветки перед публикацией.

В рамках обычной задачи опубликовать рабочую ветку, открыть PR в dev и выполнить squash-слияние в порядке, заданном правилами проекта. Авторство и русское подробное сообщение проверить для итогового коммита. Убедиться в результате интеграции. Удалять принадлежащий задаче временный worktree только после проверки его состояния и сохранности изменений.

Для релизных и срочных веток следовать отдельному маршруту из правил Git. В отчёте указать фактические SHA, результат CI, вердикт ревью и состояние PR.
