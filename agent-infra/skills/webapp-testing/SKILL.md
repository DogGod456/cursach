# Браузерные проверки

1. Владелец стенда (например, задача CI) разворачивает выбранный артефакт в выделенной среде, назначает адрес и тестовые данные. До запуска браузера сверить SHA256 бинарника или digest образа запущенного экземпляра с идентификатором кандидата из сборки. Сохранить подтверждение, адрес и результат readiness-проверки.
2. Передать браузерному процессу адрес через E2E_BASE_URL. Если адрес или подтверждение артефакта отсутствует, остановить приёмку и сообщить владельцу. Браузерный процесс управляет только своими контекстами и сессиями.
3. Запустить Python с установленными Playwright и совместимым браузером. В тесте дождаться наблюдаемого признака готовности приложения, выбрать элементы по ролям и проверить ожидаемый результат. Для разных пользователей создать отдельные контексты. Собрать результаты в рабочем каталоге запуска.
4. Владелец стенда освобождает только принадлежащие этому запуску ресурсы при успехе, ошибке и отмене. Зафиксировать идентификатор артефакта и результат проверок перед продвижением кандидата.

[Поиск элементов](examples/element_discovery.py) и [журнал браузера](examples/console_logging.py) иллюстрируют интерфейс Playwright. Селекторы и признаки готовности задаются сценарием проекта. Для отдельной HTML-фикстуры доступен [локальный пример](examples/static_html_automation.py); ему передают путь к файлу в HTML_FIXTURE.
