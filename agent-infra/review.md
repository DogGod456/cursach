# Независимое ревью

Координатор назначает выполнение и проверку разным субагентам. После каждой итерации исправлений назначает нового ревьюера с чистым контекстом. Ревью применяется к коду, планам, инструкциям и изменениям самой агентской инфраструктуры.

1. **Зафиксировать материал.** Для ветки записать SHA её вершины и SHA общей базы с целевой веткой (`git merge-base <target> <head>`). Передать полный diff от общей базы до вершины. Для плана или локальных материалов до коммита перечислить проверяемые файлы и зафиксировать их содержимое, например хешами. Учитывать новые файлы, которые обычный git diff ещё не показывает.
2. **Сформулировать задание.** Передать цель пользователя, критерии приёмки, границы изменений, версии и команды проверок. Ревьюер открывает файлы и проверяет выводы самостоятельно. Подробный ход рассуждений автора остаётся за пределами задания. Использовать локальные [инструкции](skills/requesting-code-review/SKILL.md) и [шаблон ревьюера](skills/requesting-code-review/code-reviewer.md).
3. **Проверить работу целиком.** Ревьюер проходит от входной точки до результата, исследует влияние на существующих потребителей и оценивает, смогут ли тесты обнаружить регрессию. Для плана прослеживает каждое требование до реализуемого шага и критерия приёмки. В отчёте указывает проверенную версию, ограничения проверки и все замечания. Для каждого замечания приводит место, условие возникновения и последствие.
4. **Разобрать замечания.** Исполнитель сверяет каждое с исходниками и целью. Подтверждённое исправляет и проверяет. Для спорного предъявляет воспроизводимое доказательство; вопрос о новом продуктовом требовании возвращает координатору. Сохранить вывод по каждому пункту. Использовать [receiving-code-review](skills/receiving-code-review/SKILL.md).
5. **Повторить и завершить.** Следующий новый субагент проверяет полный актуальный материал, включая исправления. Цикл завершён, когда независимый ревьюер явно вернул «замечаний нет» и выполнены проверки критериев приёмки на соответствующей версии. Если с момента ревью изменились содержимое или база интеграции, обновить сравнение, проверки и ревью до слияния. Для чисто редакционного переноса уже проверенных локальных файлов в коммит сверить их содержимое и полный состав diff. Зафиксировать итоговый SHA, вердикт ревьюера и результаты команд.
